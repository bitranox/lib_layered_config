# Development

## Make Targets

The `Makefile` is generated by bmk and rewritten by every bmk target, so the list of targets lives in
`make help`, which reads the Makefile itself. The ones used day to day:

- `make test` - the full local gate (below).
- `make push MSG="..."` - the gate, then a commit with that message and a push. `MSG=` reaches bmk as
  `BMK_COMMIT_MESSAGE` without passing through the shell, so the message may hold `;`, `$` or newlines.
- `make bump-patch` / `bump-minor` / `bump-major` - set the next version in `pyproject.toml`.
- `make release` - tag the current version and create its GitHub release.

## Test Pipeline (`make test`)

`make test` runs `bmk test`. It rewrites files before it checks them, so commit first if you want to
see what it changed. In bmk 3.33 it runs thirteen scripts in five stages:

1. `update_deps`: updates outdated dependencies to their latest releases, in `pyproject.toml` and
   `uv.lock`, and syncs `.venv`.
2. `uv lock --check`.
3. `ruff format .`, which rewrites files.
4. `ruff check --fix .`, which rewrites files.
5. The read-only checks, as one batch: `ruff format --check .`, `ruff check .`, `lint-imports` (Clean
   Architecture contracts), `pyright` (strict), `pytest` with doctests and coverage, `bandit`,
   `pip-audit`, and `shellcheck` / PSScriptAnalyzer for any shell or PowerShell scripts. The pytest
   script then uploads the coverage to Codecov when both `CODECOV_TOKEN` and the `codecovcli` uploader
   are present, and skips the upload otherwise.

`git add` a new file under `src/`, `tests/`, `docs/` or `notebooks/` before running `make test` or
`make push`. A locally built sdist ships every file there that the root `.gitignore` does not exclude,
tracked or not, so `tests/test_sdist_contents.py` fails on an untracked one and names it.

Coverage is enforced at 90% (`[tool.coverage.report] fail_under`).

## Recommended Workflow

```bash
pip install -e .[dev]
ruff format .
ruff check .
lint-imports
pyright
pytest --maxfail=1
bandit -q -r src/lib_layered_config
pip-audit
```

Use `make test` for the full gate; the individual commands help when iterating quickly.

`make test` runs `pip-audit`; `[tool.pip-audit] ignore-vulns` in `pyproject.toml` is empty, so every
advisory fails the gate.

### Formatting

- `make test` formats with `ruff format .` and applies `ruff check --fix .` itself, then checks; CI only
  checks, so commit what the local run rewrote.

Coverage is enforced at 90% for the `src/lib_layered_config` package. `py.typed` ships with the distribution so external type checkers treat the library as typed by default.

## Continuous Integration Overview

The workflows under `.github/workflows/` come from the shared CI template and are not edited here:

- `default_cicd_public.yml` runs the suite on Linux, macOS and Windows for every Python version the
  `pyproject.toml` classifiers declare, and the Quickstart notebook.
- `default_release_public.yml` publishes to PyPI through a Trusted Publisher when a `v*` tag is pushed.
- `codeql.yml` runs CodeQL.

`pyproject.toml` is the single source of truth for packaging metadata.

### Platform specifics

- No platform needs setup of its own: `make test` runs the same on Linux, macOS and Windows, and
  `make ensure` installs an external tool bmk reports missing for the current OS.

## Architecture Rules

The import-linter configuration in `pyproject.toml` enforces:

- `lib_layered_config.domain` **cannot** import from application/adapters/core.
- `lib_layered_config.application` can only depend on domain.
- `lib_layered_config.adapters` may depend on domain/application but not the reverse.

Keep runtime code side-effect free at import time. Only adapters and the composition root perform I/O.

## Release Checklist

1. Write the user-facing entries under `## [Unreleased]` in `CHANGELOG.md`.
2. Bump the version (`make bump-patch`, `bump-minor` or `bump-major`).
3. `make push MSG="..."`, then `make release`; the tag push starts `default_release_public.yml`.
4. Watch CI on the pushed commit and on the release.

## Observability Guidelines

- Use `lib_layered_config.observability.log_*` helpers inside adapters to emit structured logs.
- Set a trace identifier with `lib_layered_config.bind_trace_id("abc123")` when tracing requests.
- Domain/application layers MUST remain log-free to uphold Clean Architecture boundaries.

## Examples & Docs

- `lib_layered_config.generate.generate_examples` scaffolds commented example files for each layer (`app/`, `hosts/`, `user/`, `.env.example`).
- The suite executes these docs, so keep their examples runnable and deterministic: the docstring
  examples under `src/` (`--doctest-modules`), `docs/python-api.md`
  (`tests/e2e/test_python_api_docs.py`), the generate-examples sections of `docs/cli-reference.md` and
  `docs/python-api.md` (`tests/e2e/test_generate_examples_docs.py`), `docs/config-file-structure.md`
  (`tests/e2e/test_config_file_structure_docs.py`) and `notebooks/Quickstart.ipynb`
  (`tests/e2e/test_notebooks.py`). The README is not executed.

Happy building!
